# Building OpenRCT2 for WebAssembly (WASM / Emscripten)

OpenRCT2 can be compiled to [WebAssembly](https://webassembly.org/) using [Emscripten](https://emscripten.org/), allowing it to run directly in a web browser.

## Prerequisites

### Using Docker (Recommended)

The easiest way to build the WASM target is to use the pre-built Docker image that contains all necessary dependencies:

```bash
docker pull ghcr.io/openrct2/openrct2-build:26-emscripten
```

### Manual Setup

If you prefer to build without Docker, you will need:

- [Emscripten SDK](https://emscripten.org/docs/getting_started/downloads.html) (emsdk)
- [Ninja](https://ninja-build.org/)
- The following libraries compiled for Emscripten:
  - [ICU](https://icu.unicode.org/) (libicuuc + libicudata)
  - [libzip](https://libzip.org/)
  - [zstd](https://facebook.github.io/zstd/)

The CI build image precompiles these libraries, with the following paths assumed by the build script:

| Library | Path |
|---------|------|
| ICU headers | `/ext/icu/icu4c/source/common` |
| ICU libraries | `/ext/icu/icu4c/source/lib/` |
| libzip | `/ext/libzip/build/lib/libzip.a` |
| zstd | `/ext/zstd/build/build/lib/libzstd.a` |

## Building

### Using Docker

Run the build inside the Docker container:

```bash
docker run --rm -v $(pwd):/src -w /src \
  ghcr.io/openrct2/openrct2-build:26-emscripten \
  bash scripts/build-emscripten
```

### Using the Build Script Directly

If Emscripten is already set up in your environment, source the Emscripten environment and run:

```bash
source /path/to/emsdk/emsdk_env.sh
./scripts/build-emscripten
```

The build script performs the following steps:

1. Creates a `build/` directory
2. Configures the project with CMake using `emcmake`
3. Compiles the project with `ninja`
4. Assembles the output files into `build/www/`

## Build Output

After a successful build, the output is placed in `build/www/`:

| File | Description |
|------|-------------|
| `openrct2.js` | JavaScript glue code generated by Emscripten |
| `openrct2.wasm` | WebAssembly binary |
| `openrct2.zip` | Compressed bundle of `openrct2.js` and `openrct2.wasm` |
| `index.html` | Web page that loads and runs the game |
| `index.js` | Loader script that initialises the game |

An `assets.zip` file containing the game's data files must also be placed in the same directory as the built output before the game can run. See the [CI workflow](../../.github/workflows/ci.yml) for how this is assembled.

## Running the Built Game

The output files must be served over HTTP/HTTPS — they cannot be opened directly as local files due to browser security restrictions (CORS and SharedArrayBuffer requirements).

A minimal development server can be started with:

```bash
cd build/www
python3 -m http.server
```

Then open `http://localhost:8000` in your browser.

> **Note:** `SharedArrayBuffer` (required for threading) is only available when the page is served with the following HTTP response headers:
>
> ```
> Cross-Origin-Opener-Policy: same-origin
> Cross-Origin-Embedder-Policy: require-corp
> ```
>
> For a quick local test, [serve](https://www.npmjs.com/package/serve) and similar tools can set these headers automatically.

## Disabled Features

The WASM build disables several features that either depend on OS-level functionality or are not yet supported in the browser environment:

| Feature | CMake flag |
|---------|------------|
| Networking / multiplayer | `-DDISABLE_NETWORK=ON` |
| OpenGL renderer | `-DDISABLE_OPENGL=ON` |
| HTTP downloads | `-DDISABLE_HTTP=ON` |
| TrueType fonts | `-DDISABLE_TTF=ON` |
| FLAC audio | `-DDISABLE_FLAC=ON` |
| Discord Rich Presence | `-DDISABLE_DISCORD_RPC=ON` |

## Persistent Storage

The WASM build uses [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) via Emscripten's `IDBFS` filesystem to persist user data between sessions. Three virtual directories are mounted:

| Path | Purpose |
|------|---------|
| `/persistent` | User data (saves, config, screenshots) |
| `/RCT` | RollerCoaster Tycoon 2 original game assets |
| `/OpenRCT2` | OpenRCT2 assets (objects, title sequences, etc.) |
